1. Project Overview
The pipeline performs 2D slice-wise semantic segmentation of pancreatic CT scans into three classes — background, pancreas, tumor — using a custom architecture the notebook names CNNPyramidTransformerSeg: a Residual-CNN encoder, a Pyramid Pooling Module + Multi-Head Self-Attention transformer bottleneck, and a U-Net-style decoder with skip connections. The model supports Grad-CAM, raw attention-map visualization, and LIME for explainability.
2. Dataset
Source: Medical Segmentation Decathlon (MSD) — Task 07 (Pancreas). Loaded from dataset.json + imagesTr/labelsTr NIfTI volumes.
Classes: 3 — Background (0), Pancreas (1), Tumor (2).
Patient-level split (random, seed=42): Training 70%, Validation 15%, Testing 15%. Saved to split_70_15_15.json.
5-fold cross-validation: performed on the combined Train+Validation pool (train_ids + val_ids merged), using sklearn KFold(n_splits=5, shuffle=True, random_state=42). Saved to kfold_5.json. The held-out 15% Test set is NOT part of any fold — it is only used for final ensemble evaluation.
Environment note: dataset paths are Kaggle-specific (/kaggle/input/datasets/.../Task07_Pancreas, /kaggle/working/pancreas_project) — the developer will need to update these paths for any non-Kaggle environment.
3. Preprocessing Pipeline (as implemented in code)
Volume-level preprocessing (CTPreprocessor.preprocess_volume), applied in this order:
HU windowing / clipping — np.clip(volume, hu_min=-150, hu_max=250).
Min-max normalization — (vol - hu_min) / (hu_max - hu_min) → range [0, 1], cast to float32.
Resampling to isotropic 1.0×1.0×1.0 mm spacing using scipy.ndimage.zoom (order=1).
Per-slice preprocessing (CTPreprocessor.process_slice), applied after the volume step, per 2D axial slice:
Resize slice to 256×256 (skimage.transform.resize, mode='reflect', anti_aliasing=True).
Gaussian smoothing — sigma=0.5 (scipy.ndimage.gaussian_filter).
CLAHE — skimage.exposure.equalize_adapthist, clip_limit=0.03 (compared against 0.01/0.03/0.05 and global histogram equalization during experimentation; 0.03 was selected).
ROI-based patch extraction (ROIPatchExtractor), applied after per-slice preprocessing, on slices whose mask has ≥50 foreground pixels (min_area=50):
Compute the 2D bounding box of the non-background mask region, with a 10px margin.
Expand the box to a square using context_scale=1.5× the larger side, centered on the bbox centroid.
Crop both image and mask to that square, then resize to a fixed 128×128 patch (image: bilinear + anti-aliasing; mask: nearest-neighbor, order=0).
Slices with no foreground are skipped entirely (or fall back to the full resized 256×256 slice if extraction fails).
Final effective training resolution: img_size is reset from 256 → 128 after ROI extraction (CFG['img_size'] = ROI_EXTRACTOR.patch_size). All model training happens on 128×128 ROI patches, not full 256×256 slices.
4. Data Augmentation
Two augmentation layers exist in the notebook:
Main training augmentation (used in the actual 5-fold training loop) — an Albumentations pipeline (TRAIN_AUG) applied to every 128×128 patch: HorizontalFlip(p=0.5), VerticalFlip(p=0.3), RandomRotate90(p=0.3), ShiftScaleRotate(shift=0.05, scale=0.1, rotate=15°, p=0.5), ElasticTransform(alpha=60, sigma=4, p=0.3), GridDistortion(p=0.2), RandomCrop(96×96, p=0.3) + PadIfNeeded back to 128×128, RandomGamma(80–120, p=0.3), RandomBrightnessContrast(±0.2, p=0.4), GaussNoise(var 0.001–0.005, p=0.3), GaussianBlur(blur_limit=3, p=0.2), CoarseDropout(max_holes=4, max_h/w=12, p=0.2). Validation/test use only PadIfNeeded (no randomness).
Standalone augmentation classes (defined, demoed on sample images, but NOT called inside the actual 5-fold training loop — flagged in Section 10): TargetedZoomAug (zoom_range 0.5–1.5, p=0.5), ElasticDeformer (a second, separate elastic-deformation implementation with alpha=120, sigma=10, p=0.4 — different parameters from the Albumentations ElasticTransform above), MultiScaleDataset (random resolution per sample from [128, 192, 256], fixed 256 for val/test), and AttentionGuidedAug (saliency-driven noise/brightness augmentation using a hook on the model bottleneck, noise_inside≈0.03–0.04, noise_outside=0.005, brightness_range=(0.85,1.15), threshold≈70–75th percentile, p=0.5).
5. Model Architecture — CNNPyramidTransformerSeg
Residual-CNN encoder (4 stages, each = 2× ResBlock with BatchNorm+ReLU+Dropout and a projection shortcut) → MaxPool2d(2) between stages → Pyramid-Transformer bottleneck → U-Net decoder with skip concatenation.
Encoder channel progression: 64 → 128 → 256 → 512 (stages enc1–enc4), each followed by MaxPool2d(2).
Bottleneck (TransformerBottleneck): 1×1 conv projects 512→embed_dim → Pyramid Pooling Module (PSPNet-style, pool sizes 1/2/4/8) for multi-scale context → N stacked MultiHeadSelfAttention2D layers (standard pre-norm transformer block: nn.MultiheadAttention + LayerNorm + GELU feed-forward of size embed_dim×4) → 1×1 conv projects back to 512 channels.
Decoder: 4 stages of ConvTranspose2d(stride 2) upsampling + concatenation with the matching encoder skip + ResBlock, channel path 512→256→128→64→32, then a final 1×1 Conv2d to 3 output classes (logits, no final activation — softmax/argmax applied downstream).

Explainability module: Grad-CAM (custom GradCAMSeg class) hooked on xai_model.enc4[-1].conv1.block[0] (last encoder residual block's first conv layer), targets a chosen class channel summed over all pixels, backprops to get channel-weighted activation maps. Raw transformer self-attention weights are also visualized directly via forward hooks on the bottleneck's attention layers. LIME (lime_image, 150 perturbation samples) is additionally applied for pancreas/tumor superpixel explanations. SHAP is installed as a dependency but is not actually invoked anywhere in the notebook.
6. Loss Function (as implemented)
combined_loss = 0.6 × Dice Loss + 0.3 × weighted Cross-Entropy + 0.1 × Focal Loss (weights: dice_w=0.6, ce_w=0.3, focal_w=0.1).
Dice Loss: multi-class soft Dice, averaged over all 3 classes, smooth=1e-5.
Weighted Cross-Entropy: per-class weights CLASS_W = [0.1 background, 0.3 pancreas, 0.6 tumor] — tumor is up-weighted 6× relative to background to counter the tumor class making up only ~2–5% of labeled voxels.
Focal Loss: alpha=0.25, gamma=2.0, applied on top of standard cross-entropy.
Note: there is no explicit Boundary Loss term in the notebook's loss function, despite that being mentioned as a requirement elsewhere — see Section 11.
7. Hyperparameter Optimization
Tool used: Optuna (TPESampler, seed=42) with a MedianPruner (n_startup_trials=3, n_warmup_steps=1) — NOT the 'Aquila Optimizer' mentioned verbally by the project owner. See Section 11.
12 trials total, 3 quick-training epochs per trial, on a reduced 200-sample subset at 128×128 resolution, batch size per-trial from {4, 8}.
Search space: learning rate, batch size, dropout, transformer depth, num_heads, embed_dim, weight_decay, optimizer choice (Adam vs AdamW) — full ranges listed in the Section 5 table.
Objective (maximized): mean of (Pancreas Dice + Tumor Dice) / 2 on the validation subset after 3 epochs.
Best parameters are saved to results/best_hparams.json and used to update CFG before the main 5-fold training run.
8. Training Configuration & Procedure
Optimizer: AdamW, lr and weight_decay taken from the (Optuna-tuned) CFG.
LR schedule: CosineAnnealingLR, T_max = num_epochs (50), eta_min = 1e-6, stepped once per epoch.
Mixed precision (AMP) via torch.cuda.amp.autocast + GradScaler when a GPU is available.
Gradient clipping: max norm 1.0 (after unscaling).
Early stopping: patience=10 epochs, on the mean of (Pancreas Dice + Tumor Dice)/2 improving by more than delta=1e-4.
Procedure: for each of the 5 folds — build fold-specific train/val loaders (train uses TRAIN_AUG, val uses VAL_AUG only) from the merged train+val pool, train a fresh CNNPyramidTransformerSeg up to 50 epochs with early stopping, checkpoint the best epoch (by mean Dice) to checkpoints/fold{N}_best.pt, and log scalars (train/val loss, per-class Dice) to TensorBoard.
Final test-time inference: 5-model soft ensemble — softmax probabilities from all 5 fold checkpoints are averaged (ensemble_predict), and metrics are computed from that averaged probability map on the held-out test set.

11. Discrepancies Between the Reference PDF and the Notebook
The reference PDF you sent describes a different model and different reported results than what the notebook actually implements. Flagging these clearly so you can check with your supervisor which is correct:
Architecture: PDF describes AttnUNet + pretrained EfficientNet-B3 backbone + 4-layer Graph Attention Network (GAT), with an Attention U-Net decoder using gated skip connections (att1–att4). The notebook implements a plain Residual-CNN encoder (no EfficientNet, no pretraining) + Pyramid-Pooling + standard Multi-Head Self-Attention transformer bottleneck (no graph attention) + a plain U-Net decoder (no attention gates).
Hyperparameter optimizer: PDF's earlier verbal spec mentioned 'Aquila Optimizer.' The notebook uses Optuna (TPE + Median Pruner).
Loss function: PDF specifies Cross-Entropy(0.30) + Dice(0.45) + Focal(0.25) + Focal Tversky(0.50) (α=0.3, β=0.7, γ=1.33). The notebook uses Dice(0.6) + weighted CE(0.3) + Focal(0.1) — no Focal Tversky term at all.
Batch size: PDF says 16. Notebook default/search space tops out at 8.
Preprocessing values differ: PDF's HU window is -100 to +250 with CLAHE clip 2.0/tile(8,8) and resize straight to 128×128 with dynamic class weights (0.0004/0.0822/2.9174) and 8-pass TTA. Notebook uses HU window -150 to +250, CLAHE clip_limit=0.03 (adaptive-hist scale, not the OpenCV 0–∞ clip-limit scale the PDF uses — these are not directly comparable numbers), a 256px intermediate resize before a separate 128×128 ROI-patch crop, fixed class weights [0.1, 0.3, 0.6], and no TTA at inference (only 5-fold ensembling).
Reported test metrics: the PDF lists specific final numbers (e.g., Tumor Dice 57.80%, Tumor ROC-AUC 93.40%). These appear to be results from the PDF's different model/pipeline, not the notebook — the notebook does not contain these numeric results as fixed outputs; they only appear after training actually runs on real hardware.
Given your instruction, this document treats the notebook as authoritative for the architecture and all training parameters, since "the model used is different" from the PDF. Preprocessing and dataset handling are aligned in category (HU windowing → normalize → CLAHE → ROI → resize) between the two sources, but not in exact numeric values — the values in Sections 3, 5, 6, 7, 8 above are the notebook's actual numbers.
